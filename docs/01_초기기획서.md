# 01. 초기 기획서

작성 2026-11-24 · 상태: 기획 완료, 구현 전

## 1. 배경

데이터 엔지니어(DE)와 MLOps 직무에서 공통으로 보는 역량은 도구를 설치해 본 경험이 아니라 다음과 같습니다.

- 데이터를 **유실·중복 없이** 받는가
- 늦게 오거나 잘못된 데이터를 **조용히 버리지 않고** 처리하는가
- 같은 작업을 다시 돌려도 **결과가 같은가** (멱등성)
- 장애가 나도 **복구되는가**
- 모델이 어떤 데이터로 학습됐는지 **추적·재현되는가**
- 운영 중 모델 성능을 **측정하고 개선하는가**

이 프로젝트는 이 역량을 실제 실시간 데이터로 증명하는 것이 목적입니다. 데이터 소스로는 업비트를 선택했습니다. 키 없이 24시간 실시간 데이터를 받을 수 있고, 공식 1분 캔들이 있어서 **직접 만든 집계가 맞는지 외부 기준으로 채점할 수 있기 때문**입니다.

## 2. 목표

### 한 문장 목표
업비트 실시간 거래 데이터를 유실·중복 없이 받아 믿을 수 있는 분석 테이블과 AI 학습용 데이터셋으로 만들고, 그 위에서 예측 → 자동 채점 → 재학습이 도는 파이프라인을 구축하고 수치로 검증한다.

### 세부 목표
| # | 목표 | 증거 |
|---|---|---|
| G1 | 실시간 수집 파이프라인 (Kafka → Spark → Delta Lake) | 30일 연속 운영 기록 |
| G2 | Bronze → Silver → Gold 정제와 스타 스키마 | 테이블 명세, 품질 검사 결과 |
| G3 | 정확성 검증 | 공식 1분 캔들과의 일치율 |
| G4 | 신뢰성 검증 | 장애·중복·지연 시나리오 통과, 복구 시간 |
| G5 | AI-ready 데이터셋 | 버전 고정된 학습셋, 누수 검사 통과 |
| G6 | MLOps 한 바퀴 | 실시간 예측, 5분 뒤 자동 채점, 성능 하락 감지, 재학습·교체 기록 |
| G7 | 대시보드 | Grafana: 코인별 위험도, 예측 vs 실제, 모델 성적표, 파이프라인 상태 |

## 3. 범위

### 포함
- 대상: KRW 마켓 거래대금 상위 10개 코인 (시작 시점에 확정하고 고정)
- 데이터: 체결(trade), 호가(orderbook), 현재가(ticker), 1분 캔들(REST), 마켓 목록과 주의 표시(REST)
- 예측: 코인별 "앞으로 5분 안에 급변동할 확률"을 1분마다 산출
- 모델: 규칙 기반 → 로지스틱 회귀 → LightGBM
- 대시보드: Grafana

### 제외
- 주문, 자동매매, 투자 판단이나 수익률 주장
- 대용량 처리 주장 (데이터 규모가 크지 않으므로 "정확성과 운영"을 강조)
- 클라우드 배포 (마지막에 선택 사항으로 검토)

### 확장 후보 (본 범위 완료 후)
| 확장 | 조건 |
|---|---|
| 업비트 주의 종목 조기 감지 | 주의 표시 이력이 학습 가능한 만큼 쌓였을 때 |
| 김치 프리미엄 모니터 | 해외 거래소 시세와 분 단위 환율 소스를 확보했을 때 |
| 알림 봇 (텔레그램·디스코드) | 6단계 완료 후 |
| 로컬 LLM(Qwen) 해설 | 모든 단계 완료 후, 위험도가 높을 때만 한국어 해설 생성 |

## 4. 성공 기준

| 기준 | 목표 | 비고 |
|---|---|---|
| 연속 운영 | 30일 이상 | 장애 발생 시 장애 보고서 작성 |
| 공식 캔들 일치율 | 측정 후 목표 확정 | 3분 시험에서는 100% 일치 |
| 체결 유실 | 수집기가 살아 있던 구간에서 0건 | 끊긴 구간은 갭으로 기록 |
| 중복 | Silver에서 (market, sequential_id) 기준 0건 | |
| 재실행 멱등성 | 같은 입력 재계산 시 결과 해시 동일 | |
| 모델 | 규칙 기반 대비 개선 여부를 정직하게 보고 | 개선이 없어도 실패가 아님 |
| MLOps | 재학습·교체가 최소 1회 이상 실제로 일어난 기록 | 승격 기준 통과 시에만 교체 |

## 7. 리스크와 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| 도구가 많아서 설정만 하다 지침 | 진행 중단 | 단계마다 돌아가는 것을 먼저 만들고 다음 도구를 붙임. 0단계는 Python만 사용 |
| PC 메모리 부족 | 동시 실행 불가 | L0 단일 구성으로 시작, Airflow는 늦게 켬, 메모리 실측 |
| 업비트 연결 끊김 | 데이터 공백 | 재연결, 갭 기록, REST 캔들 백필, L1에서 수집기 2대 |
| 예측 성능이 낮음 | 모델 결과가 약해 보임 | 목표는 파이프라인 신뢰성. 기준선 대비 결과를 정직하게 보고 |
| 주제가 흔함 | 차별화 부족 | 공식 캔들 대사, 30일 운영 보고서, 자동 채점·재학습 기록으로 차별화 |
| 이용약관 위반 가능성 | 공개 제약 | 약관 확인 전까지 원본 데이터 비공개, 요청 제한 준수 |
