# 02. 주제와 문제 정의

> 결정의 현재 상태는 [09_결정현황.md](09_결정현황.md)가 기준입니다. 이 문서의 ML 항목(라벨, 평가)은 ML 단계 시작 전에 2주 실시간 데이터 기준으로 다시 검토합니다.

## 1. 주제

**업비트 실시간 시장 이상 신호 플랫폼**

코인별로 "앞으로 5분 안에 급변동할 확률"을 1분마다 예측하고, 5분 뒤 실제 결과로 자동 채점하며, 성능이 떨어지면 재학습하는 시스템입니다.

## 2. 왜 이 문제인가

| 이유 | 설명 |
|---|---|
| 정답이 자동으로 생김 | 5분이 지나면 실제 변동폭이 나오므로 사람이 라벨을 붙일 필요가 없음 |
| 운영 중 채점 가능 | 대부분의 ML 서비스는 운영 중 정답을 알기 어렵지만, 이 문제는 5분 뒤 바로 알 수 있음. 그래서 드리프트 감지와 재학습을 실제 수치로 보여줄 수 있음 |
| 시장 상태가 계속 바뀜 | 시간대·요일·이벤트에 따라 분포가 달라져서 재학습이 필요한 이유가 자연스럽게 생김 |
| 확장 경로가 있음 | 나중에 업비트의 실제 주의 표시를 정답으로 쓰는 문제로 업그레이드 가능 |

이 프로젝트에서 예측은 **파이프라인과 MLOps를 증명하기 위한 소비자**입니다. 예측 성능 자체가 목표는 아닙니다.

### 왜 5분이고, 왜 더 긴 기간(예: 다음 분기)이 아닌가

예측 기간은 **데이터 단위와 수집 기간**에 맞춰야 합니다. 모델은 "같은 질문 + 이미 알려진 정답" 쌍을 많이 봐야 배웁니다.

| 질문 | 2주 수집 후 학습 샘플 | 채점 |
|---|---|---|
| 5분 뒤 급변동? | 약 20,160분 × KRW 마켓 약 300개 중 유효 구간 (계산, 유효 구간 수는 미측정) | 5분 뒤 매번 |
| 다음 분기 가격? | 0개 (분기가 한 번도 끝나지 않음) | 몇 달 뒤 한 번 |

분기 단위라면 과거 일봉(REST)만으로 충분해서 실시간 수집이 필요 없어지고, 채점이 한 번뿐이라 예측 → 채점 → 재학습 루프도 돌릴 수 없습니다. 또 짧은 구간의 **변동성**은 최근 변동성이 큰 구간에 큰 변동이 이어지는 성질(변동성 군집) 때문에 가격 방향보다 상대적으로 예측이 되는 편입니다. 바이낸스 BTC 2022-05 측정에서 5분 수익률의 자기상관은 −0.036, 변동폭의 자기상관은 0.716이었습니다 ([09 문서 M1](09_결정현황.md)).

## 3. 예측 문제의 정확한 정의

### 3.1 단위
- **한 건의 예측 = 마켓 하나 × 1분**
- 시각 `t`는 1분 구간의 시작 시각입니다. 예: `t = 12:08`은 12:08:00~12:08:59 구간입니다.
- 예측은 `t` 구간이 끝난 직후(12:09:00 이후)에, 그때까지의 데이터로만 합니다.

### 3.2 정답 (라벨)
`t` 다음 5개의 1분 구간(`t+1` ~ `t+5`) 동안의 **가격 변동폭**을 계산합니다.

```
future_range(t) = ( max(high[t+1..t+5]) − min(low[t+1..t+5]) ) / close[t]

label(t) = 1   if future_range(t) ≥ θ_market
           0   otherwise
```

- `θ_market`(임계값)은 **마켓마다 따로** 정합니다. BTC와 소형 알트코인은 평소 변동폭이 크게 다르기 때문입니다.
- `θ_market`은 **학습 기간의 유효 구간만으로** 계산한 `future_range`의 상위 20% 경계값(80번째 백분위수)입니다. 평가 기간 데이터를 쓰면 누수가 됩니다. 전체 구간으로 계산하면 거래가 적은 코인은 경계값이 0.00%가 되므로 유효 구간만 씁니다 ([09 문서 M5](09_결정현황.md)).
- 따라서 양성(1) 비율은 학습 기간에서 약 20%이고, 평가 기간에서는 시장 상황에 따라 달라집니다.
- 20%는 제안 값이고 상위 10%도 함께 평가합니다 ([09 문서 7절](09_결정현황.md)).

### 3.3 체결이 없는 분과 유효 구간
- KRW 전체를 예측하므로 체결이 거의 없는 코인도 있습니다. 2026-11-23 하루 기준 순위 101위 이하 코인의 1분 캔들 수 중앙값은 1,440분 중 275개였습니다 ([09 문서 M2](09_결정현황.md)).
- 체결이 없는 분은 캔들이 없으므로, 직전 종가로 채우고 `is_filled = true`로 표시합니다.
- **유효 구간**: `t+1..t+5` 안에 체결이 k건 이상인 구간만 라벨을 만들고 채점합니다. k는 미정입니다 ([09 문서 7절](09_결정현황.md)).
- `t+1..t+5` 중 **수집 공백(갭)**이 있는 구간은 라벨을 만들지 않습니다(`label = null`). 체결이 없는 것과 수집이 끊긴 것은 다릅니다.

### 3.4 예측 출력
| 필드 | 의미 |
|---|---|
| `p_spike` | 5분 안에 급변동할 확률 (0~1) |
| `model_version` | 예측에 사용한 모델 버전 |
| `predicted_at` | 예측을 만든 시각 |

대시보드에는 `p_spike`를 0~100% 위험도로 표시합니다. 알림을 보낼 때의 기준값은 검증 데이터에서 정밀도와 재현율을 보고 정합니다.

## 4. 평가

### 4.0 성적표 분리
- **대표 성적**: 평소 거래가 충분한 코인(유니버스)의 유효 구간. 유니버스는 최근 N일 동안 유효 구간 비율이 Y% 이상인 코인이고, 매일 전날까지 데이터로 다시 계산합니다 (N, Y 미정).
- **별도 성적**: 유니버스 밖 코인의 유효 구간.
- 두 성적표 모두 기준선과 비교하고, 기준선을 못 이기는 그룹도 그대로 기록합니다 ([09 문서 8절](09_결정현황.md)).

### 4.1 기준선과 모델
| 이름 | 내용 | 역할 |
|---|---|---|
| B0 | 항상 0으로 예측 | 정확도 착시 확인용 (양성 20%면 정확도 80%가 나옴) |
| B1 규칙 | 최근 1분 거래량이 최근 60분 평균의 k배 이상이면 1 | 머신러닝 없이 어디까지 되는지 |
| M1 | 로지스틱 회귀 | 가장 단순한 학습 모델 |
| M2 | LightGBM | 메인 모델 |

### 4.2 지표
| 지표 | 이유 |
|---|---|
| **PR-AUC** (주 지표) | 양성이 적은 문제에서 정확도보다 적합 |
| 정밀도·재현율 (알림 기준값에서) | "알림 10번 중 몇 번이 맞았나", "급변동 10번 중 몇 번을 잡았나" |
| Brier score | 확률이 실제 비율과 얼마나 맞는지 (위험도 표시의 신뢰성) |
| 마켓별·시간대별 PR-AUC | 특정 코인이나 시간대에서만 잘 되는지 확인 |

### 4.3 평가 방식
- **오프라인 평가**: 시간순으로 train / validation / test를 나누고, 경계마다 최소 5분(라벨 기간) 이상의 간격을 둡니다.
- **온라인 평가**: 운영 중 모든 예측을 5분 뒤 자동 채점하고, 최근 24시간 PR-AUC를 계속 계산합니다.

## 5. 결과 해석 원칙

- 기준선(B1)보다 나은지 정직하게 보고합니다. 차이가 없으면 "규칙으로 충분했다"도 유효한 결론입니다.
- 결과를 본 뒤 임계값, 분할, 평가 지표를 바꾸지 않습니다. 바꿔야 하면 새 실험 버전으로 기록합니다.
- 이 예측은 투자 판단 근거가 아니며, 그렇게 표현하지 않습니다.

## 6. 확장: 업비트 주의 종목 조기 감지

마켓 목록 API의 `market_event.caution`에는 업비트가 직접 붙이는 주의 표시가 있습니다.

| 필드 | 의미 |
|---|---|
| `PRICE_FLUCTUATIONS` | 가격 급등락 |
| `TRADING_VOLUME_SOARING` | 거래량 급증 |
| `DEPOSIT_AMOUNT_SOARING` | 입금량 급증 |
| `GLOBAL_PRICE_DIFFERENCES` | 해외 가격과 차이 |
| `CONCENTRATION_OF_SMALL_ACCOUNTS` | 소수 계정 집중 |

1단계부터 5분마다 마켓 목록을 저장해 표시 변화 이력을 쌓습니다. 2주 운영이 끝났을 때 표시가 붙은 횟수를 세어서, 학습할 만큼 충분하면 "주의 표시가 붙기 전 N분 안에 감지"를 두 번째 예측 문제로 추가합니다. 이 경우 정답이 거래소의 실제 판단이라 의미가 더 분명해집니다.

마켓 목록은 KRW 마켓 전체를 기록합니다.
