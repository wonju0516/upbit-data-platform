# 06. 신뢰성 검증 계획

이 프로젝트의 핵심 증거입니다. DE 목표는 **2주(14일) 연속 운영 동안 유실·중복·정확성·지연·장애 회복을 수치로 보여주는 것**입니다([09 문서 1절](09_결정현황.md)). 합격 기준값은 아직 정하지 않았습니다. 모든 시나리오는 **스크립트로 재현**할 수 있어야 하고, 결과는 숫자로 README와 운영 보고서에 남깁니다.

## 0. 스모크 테스트와 시연 테스트 (필수)

검증은 **정해 둔 스크립트로만** 합니다. 그때그때 명령을 지어내 돌리지 않습니다. 같은 절차를 반복해야 결과를 비교할 수 있고, 시험이 본 데이터를 건드리는 일을 막을 수 있습니다.

| 종류 | 언제 | 무엇 | 통과 기준 |
|---|---|---|---|
| 스모크 테스트 | 코드·설정을 고친 뒤 커밋 전, 긴 측정이나 2주 운영 시작 전 | 짧게 실제로 처음부터 끝까지 한 바퀴 돌려 기본 흐름이 살아 있는지만 봄 | 스크립트가 `PASS` |
| 시연 테스트 | 각 단계의 완료 기준을 확인할 때 | 사람이 보는 앞에서 같은 스크립트를 돌려 결과(숫자)를 보여 줌 | 스크립트가 `PASS`, 결과를 해당 이슈에 댓글로 남김 |

지켜야 할 것:
- 시험은 **시험 전용 이름**(`producer-smoke-…`, `producer-t19` 등)과 **시험 전용 폴더**(`data/ingest-smoke/` 등)를 씁니다. 본 수집의 상태 파일·버퍼와 섞이지 않습니다.
- 시험 메시지도 같은 Kafka 토픽에 들어갑니다. Silver는 `producer_id`가 `producer-a`가 아닌 행을 걸러 내고, 2주 운영 시작 전에는 토픽을 비우고 시작합니다.
- 스모크 테스트는 측정이 아니므로 원장에 쓰지 않습니다.
- 실패하면 고친 뒤 **같은 스크립트로** 다시 돌려 `PASS`를 확인합니다.

| 단계 | 스크립트 | 확인하는 것 |
|---|---|---|
| 1 수집기 | `tests/scenarios/smoke_ingest.py` (3분, 60초에 체결 연결을 일부러 끊음). 컨테이너로 돌렸을 때는 `--check-only <producer_id>`로 확인만 | 체결·호가·현재가·마켓 목록이 Kafka에 들어감, 끊은 공백 1건이 기록되고 `LOCAL`로 판정, 체결 REST 보충분이 체결 토픽에 들어감, 남은 버퍼 없음 |

## 3. 운영 지표 (Prometheus)

수집 첫날부터(2단계) 아래 지표를 Grafana로 봅니다. 시스템 자원(메모리, CPU, 디스크 여유)도 함께 봅니다.

| 지표 | 의미 |
|---|---|
| `ingest_messages_total{type, producer}` | 수집 메시지 수 |
| `ingest_lag_ms` | 업비트 전송 시각 → Producer 수신 지연 |
| `ingest_reconnects_total` | 재연결 횟수 |
| `kafka_consumer_lag` | Kafka 적체 |
| `pipeline_event_to_gold_ms` | 체결 시각 → Gold 확정 지연 |
| `quarantine_rows_total{reason}` | 격리 건수 |
| `prediction_latency_ms` | 캔들 확정 → 예측 완료 |
| `prediction_missing_total` | 예측 누락 분 수 |
| `table_last_updated_seconds{table}` | 테이블별 마지막 갱신 후 지난 시간 (신선도) |
| `ingest_spool_messages` | Kafka에 못 보내고 수집기에 쌓인 메시지 수 |

## 3-0. 2주 판정

핵심 기준은 ① 체결 유실·중복 0건, ② 공식 캔들 일치율이고 통과·실패를 판정합니다. 보조 기준은 ③ 지연·경보 도착 시간, ④ 장애 시험입니다. 지연·경보 시간은 측정값으로 보고하고, 장애 시험은 시험별로 판정합니다. 호가는 공식 기준이 없어 공백 창만 보고합니다 ([09 문서 1절](09_결정현황.md)).

## 3-1. 공백 분류

2주 동안 생긴 공백은 하나도 빼지 않고 아래 중 하나로 분류해 기록합니다.

| 분류 | 예 | 기록 |
|---|---|---|
| 계획 정지 | 사용자가 PC를 꺼야 할 때 | 정지 절차 실행 여부, 시작·끝, 이유 |
| 장애 시험 | T06, T12 등 일부러 일으킨 장애 | 시험 번호, 시작·끝 |
| 실제 장애 | 인터넷 끊김, 프로세스 다운 | 장애 보고서(5절) |
| 외부 원인 | 업비트 점검, 거래 없음 | 근거(공지, 공식 캔들도 없음) |
