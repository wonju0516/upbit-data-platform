# 06. 신뢰성 검증 계획

이 프로젝트의 핵심 증거입니다. 모든 시나리오는 **스크립트로 재현**할 수 있어야 하고, 결과는 숫자로 README와 운영 보고서에 남깁니다.

## 1. 정확성: 공식 캔들 대사

| 항목 | 내용 |
|---|---|
| 방법 | 직접 만든 `fact_candle_1m`과 업비트 REST 1분 캔들(`ref_candle_official`)을 마켓 × 1분 단위로 비교 |
| 비교 항목 | 시가, 고가, 저가, 종가, 거래량 |
| 판정 | 가격은 완전 일치, 거래량은 `|차이| < 1e-8` |
| 실행 | 매일 전날 분량 (`recon_candle_1m`, `recon_daily_summary`) |
| 보고 | 일치율 = 일치한 분 / 공백 없는 전체 분 |
| 사전 시험 결과 | 2026-11-24, KRW-BTC 3분, 체결 1,025건: **3분 모두 OHLCV 일치** |

불일치가 나오면 원인을 분류합니다: 수집 공백, 중복, 늦게 온 데이터(watermark 밖), 시각 경계 처리, 공식 캔들 쪽 정정. 분류 결과 자체가 운영 보고서의 내용이 됩니다.

## 2. 장애·데이터 이상 시나리오

| # | 시나리오 | 주입 방법 | 통과 기준 | 단계 |
|---|---|---|---|---|
| T01 | 중복 전송 | 같은 메시지를 Kafka에 두 번 발행 | Silver에서 1행 | 2 |
| T02 | 재연결 SNAPSHOT 중복 | 수집기 WebSocket을 강제로 끊고 재연결 | 재연결 직후 SNAPSHOT 체결이 중복으로 쌓이지 않음 | 2 |
| T03 | 불량 메시지 | 스키마가 깨진 메시지, 가격 0인 메시지 발행 | 파이프라인은 계속 동작, `silver_quarantine`에 사유와 함께 저장 | 2 |
| T04 | 늦게 온 데이터 | 체결 시각을 과거로 둔 메시지를 늦게 발행 | watermark 안이면 실시간 반영, 밖이면 일일 재계산에서 반영되고 `revision` 증가 | 3 |
| T05 | 재실행 멱등성 | 같은 날짜 일일 재계산을 두 번 실행 | 행 수와 내용 해시 동일 | 3 |
| T06 | 수집기 장애 (L0) | Producer kill 후 재시작 | 끊긴 구간이 `silver_ingest_gap`에 기록되고 REST 캔들로 백필 | 1 |
| T07 | Spark 잡 장애 | 스트리밍 잡 kill 후 재시작 | 체크포인트에서 재개, 중단 없이 돌린 경우와 Silver 행 수 동일 | 1 |
| T08 | PostgreSQL 장애 | DB 중지 후 재시작 | 수집·정제는 계속, 재시작 후 대시보드 테이블이 따라잡음 | 3 |
| T09 | 예측 서비스 장애 | 예측 서비스 kill 후 재시작 | 재시작 후 최신 champion 로드, 빠진 분은 예측 누락으로 기록 | 6 |
| T10 | 모델 롤백 | champion을 이전 버전으로 되돌림 | 1분 안에 이전 모델로 예측 | 6 |
| T11 | 수집기 1대 장애 (L1) | Producer A만 kill | 공백 없음 | 7 |
| T12 | Kafka 브로커 1대 장애 (L1) | 브로커 1대 kill, 30분 후 재기동 | 수집·처리 계속, 재기동 후 복제본 동기화 | 7 |
| T13 | Kafka 브로커 2대 장애 (L1) | 브로커 2대 kill | 쓰기 거부, 경보 발생, 복구 후 공백이 기록됨 (유실을 숨기지 않음) | 7 |
| T14 | Spark 워커 장애 (L1) | 워커 1대 kill | 처리 계속, 지연 증가량 기록 | 7 |
| T15 | 예측 서비스 1대 장애 (L1) | 부하 중 1대 kill | HAProxy가 자동 제외, 실패 요청 수와 전환 시간 기록 | 7 |
| T16 | DB 복원 | PostgreSQL 볼륨 삭제 후 백업 복원 | MLflow 기록 복원, 복원 시간 기록 | 7 |
| T17 | PC 재부팅 | 전체 재부팅 | 자동 기동, 꺼진 구간이 공백과 백필 범위로 기록 | 7 |

## 3. 운영 지표 (Prometheus)

| 지표 | 의미 |
|---|---|
| `ingest_messages_total{type, producer}` | 수집 메시지 수 |
| `ingest_lag_ms` | 업비트 전송 시각 → Producer 수신 지연 |
| `ingest_reconnects_total` | 재연결 횟수 |
| `kafka_consumer_lag` | Kafka 적체 |
| `pipeline_event_to_gold_ms` | 체결 시각 → Gold 확정 지연 |
| `quarantine_rows_total{reason}` | 격리 건수 |
| `prediction_latency_ms` | 캔들 확정 → 예측 완료 |
| `prediction_missing_total` | 예측 누락 분 수 |
