# RULES — 저장소 규칙 (v1.1)

이 저장소에서 사람과 AI 에이전트가 함께 지키는 규칙입니다. 요지는 [AGENTS.md](../AGENTS.md)에 있고, 본문은 이 문서가 기준입니다. 설계 결정은 [09_결정현황.md](09_결정현황.md)에 있습니다.

지금은 **DE 단계**라서 DE에 필요한 규칙만 적용합니다. ML에만 쓰는 규칙(평가 지표 고정 태그, 최종 평가 lockbox, 교차 측정·탐색 예산)은 ML 단계 시작 전에 이 문서에 추가합니다.

## 1. 세션 시작과 끝

### 시작할 때 (상태 복원)

```bash
git log --oneline -20
git status
cat STATE.md                          # 지금 · 다음 할 일 · 열린 질문
tail -n 15 experiments/LEDGER.tsv     # 최근 측정
```

### 끝낼 때 (빠뜨리지 않음)

- 돌린 테스트·측정과 결과를 그대로 보고합니다. 못 돌렸으면 못 돌렸다고 씁니다.
- `STATE.md`의 진행표 · 다음 할 일 · '최근 변경' 맨 위 한 줄을 고칩니다.
- 새로 정한 것은 `STATE.md` '결정 기록'에 한 줄을 쓰고, 기준 문서(`docs/09_결정현황.md` 등)도 고칩니다.
- 측정 결과는 원장에 남기고 커밋합니다. **커밋되지 않은 결과는 없는 결과입니다.**
- `git status`를 깨끗하게 두거나, 남긴 이유를 커밋이나 `STATE.md`에 적습니다.

## 2. 하지 않는 것 (에이전트 포함 모두)

- `--no-verify`로 훅을 건너뛰기. 테스트·허용 오차·제약을 약하게 고쳐서 통과시키기
- 원장 행 고치기·지우기. 해시를 손으로 적기 (정정은 새 행)
- 비밀값(키·토큰·비밀번호·웹훅 주소·`.env` 값)을 파일·로그·커밋에 쓰기. 예시는 `.env.example`에 **이름만**
- 묻지 않고: 대용량 다운로드, 프로그램 설치, 시스템 설정 변경, 클라우드 리소스 생성, Docker처럼 무거운 프로그램 켜기
- 승인 없이 `git push`, force push
- 다른 프로젝트의 환경·폴더 고치기
- 기준 문서에 없는 테이블·컬럼·API·오류 코드·이름을 새로 만들기 → 먼저 문서를 고치자고 말합니다
- 같은 원인으로 검증이 2번 실패하면 멈추고 사람에게 알립니다
- 수집 데이터·데이터셋·모델 파일을 커밋하기 (업비트 Open API 이용약관 제5조)

## 3. GitHub 작업 흐름

### 3.1 한 바퀴

```
(이슈) → main에서 코드 커밋 → (측정 → record 커밋) → push → CI 통과 확인 → 이슈 닫기
```

- 작업 전에 `gh issue view <번호>`로 완료 조건과 기준 문서를 읽습니다.
- **모든 작업은 `main`에서 합니다. 브랜치와 PR을 만들지 않습니다 (사용자 지시, 2026-11-26).** 측정 결과가 어느 코드에서 나왔는지는 원장의 `git_sha`와 따로 두는 `record` 커밋으로 추적합니다.
- 이슈는 측정·기능·버그를 추적할 때 만들고, 닫는 커밋 본문에 `Closes #<번호>`를 씁니다.
- **이슈 만들기 (사용자 지시, 2026-11-25):** 작업에 필요한 이슈는 에이전트가 묻지 않고 만들고, 만든 뒤 링크를 알립니다. 커밋과 `main` push는 사용자가 요청할 때만 합니다.
  - 만들기 전에 저장소 공개 여부를 확인합니다(`gh repo view --json visibility`). **공개(PUBLIC)이면 묻지 않고 만들기를 멈추고 매번 묻습니다.**
  - **개인 정보는 저장소가 비공개여도 어디에도 남기지 않습니다 (사용자 지시, 2026-11-26).** 커밋 메시지·커밋되는 파일·그림·이슈·CI 로그는 한 번 남으면 지우기 어렵고, 공개로 바꾸면 지난 것까지 모두 보입니다. 쓰지 않는 것: 비밀값, 수집 데이터 내용, IP, 계정 이름, 이메일, PC 경로, 집 네트워크 주소. 커밋 작성자는 GitHub 익명 이메일(noreply)만 씁니다.
  - 이슈는 Mac의 `gh`로 만듭니다(PC에는 계정 로그인이 없음). Mac `gh`가 로그인되어 있지 않으면 멈추고 사용자에게 `gh auth login`을 요청합니다.

### 3.1-1 공개로 바꾸기 전에

저장소 공개 전환은 사용자가 정합니다. 바꾸기 전에 아래를 확인합니다.

| 확인 | 방법 |
|---|---|
| 커밋 기록 전체에 비밀값·개인 정보·데이터 없음 | 기록 전체 검사 (pre-commit 훅과 같은 패턴 + IP·경로·계정) |
| 이슈·PR 본문과 댓글 | `gh issue list --state all`, `gh pr list --state all`로 훑어보기 |
| CI 로그에 비밀값이 찍히지 않음 | Actions 실행 기록 확인 |
| 업비트 약관 (09 문서 9-1절) | 가격 차트 화면·데이터가 문서나 이슈에 없음 |
| README | 프로젝트 소개와 한계 문서 링크 |

### 3.2 브랜치

`main` 하나만 씁니다. 훅과 `./verify.sh`를 통과한 커밋만 push합니다. 예외는 Dependabot이 보안 구멍을 고치려고 만드는 PR뿐이고, 머지 여부는 사람이 정합니다.

### 3.3 커밋 메시지

```
<type>(<scope>): <제목>

<본문 — 무엇이 아니라 왜>

<트레일러 — 기계가 읽는 계보>
```

- 제목은 72자 이하, 마침표 없음, 한국어 평서문("~한다"). 제목과 본문 사이는 빈 줄.
- 이슈 번호는 트레일러로 붙입니다: `Refs: #12`
- 에이전트가 만든 커밋은 `Co-Authored-By:` 트레일러를 남깁니다.

| type | 언제 | 필수 트레일러 |
|---|---|---|
| `record` | 측정 결과 기록 (원장 행 + 산출물) | `Run-Id`, `Ledger`, `Config-SHA256` |
| `fix` | 잘못된 동작 수정 | `Invalidates` (무효가 된 결과의 Run-Id, 없으면 `none`) |
| `upgrade` | 동작은 같고 속도·구조가 나아짐 | — |
| `feat` | 새 구성요소·스크립트·기능 | — |
| `docs` | 문서 | — |
| `chore` | 환경·설정·의존성·훅 | — |
| `revert` | 되돌리기 | — |

`fix`와 `upgrade`의 경계: 결과가 틀렸었나? 틀렸으면 `fix`입니다.

**scope 목록** (파이프라인 단계 기준):

| scope | 대상 |
|---|---|
| `ingest` | 수집기, Market Poller, 0단계 수집 스크립트 |
| `kafka` | Kafka 설정, 토픽 |
| `bronze` · `silver` · `gold` | 각 계층 |
| `recon` | 공식 캔들 대사 |
| `serve` | PostgreSQL `serve_*`, FastAPI |
| `web` | React 화면 |
| `monitor` | Prometheus, Grafana, 경보 |
| `infra` | Docker Compose, Airflow, 훅, CI, 도구 |
| `env` | Python 환경, 하드웨어 기록 |
| `docs` | 문서 |

scope 목록은 `tools/check_commit_msg.py`, `.githooks/commit-msg`, 이 표 세 곳을 같은 커밋에서 함께 고칩니다.

### 3.4 기계가 막는 것

| 장치 | 검사 |
|---|---|
| `commit-msg` 훅 | 제목 형식 · type/scope 목록 · 72자 · 마침표 · 빈 줄 · 필수 트레일러 · sha256 형식 · `Run-Id`/`Invalidates`가 원장에 실재(인덱스 기준) · record 커밋에 코드 섞임 |
| `pre-commit` 훅 | 5MB 초과 · 데이터·모델 바이너리 · 금지 경로(`data/`, `_private/`, `.env`) · 비밀값 모양 · `.ipynb` 출력 셀 · 원장 append-only |
| CI | 위 검사 + 테스트를 다시 돌림. 실패하면 이슈를 자동으로 만듦 |
| `verify.sh` | 커밋 전에 한 번에: 린트(Ruff) → 포맷 → 테스트 → 원장 → push 안 한 커밋 메시지 |

- 훅 본체는 Python(`tools/`)이고 표준 라이브러리만 씁니다. `.githooks/`의 sh 파일이 Python을 부르고, Python이 없으면 최소 형식만 sh로 검사합니다.
- 훅은 작업 트리가 아니라 **인덱스**(커밋될 내용)를 봅니다.
- 클론 직후 한 번: `git config core.hooksPath .githooks`
- 규칙 하나를 끄려면 그 줄만 끄고 이유를 적습니다. 규칙을 통째로 빼지 않습니다.

### 3.5 PR과 이슈

- **CI 실패 이슈**: push에서 CI가 실패하면 `CI 실패: <브랜치>` 이슈를 만듭니다. 같은 브랜치에 이미 열려 있으면 새로 만들지 않고 댓글만 답니다. 다음 push에서 통과하면 자동으로 닫습니다. PR에서 실패하면 이슈 대신 PR 화면에 표시됩니다.
- 저장소는 2026-11-26부터 공개입니다. `main`에는 강제 push와 브랜치 삭제만 막는 보호가 켜져 있고(관리자 포함), PR이나 검사 통과는 요구하지 않습니다. `main` 하나만 쓰므로 push 전에 CI와 같은 검사(`./verify.sh`)를 통과시키는 것으로 대신하고, push 뒤 CI 결과를 확인합니다.

- PR 템플릿(Dependabot 보안 업데이트 PR 확인용으로만 남김): 무엇을 했나 · `Closes #` · 확인 체크리스트 · 돌린 명령과 결과 그대로 · 볼 곳
- 이슈 템플릿: **측정**(무엇을 재나 · 방법 · 표본 범위 · 기록할 지표 · 완료 조건), **기능**(scope · 무엇을 · 완료 조건 · 기준 문서), **버그**(재현 · 기대와 실제 · 무효가 될 수 있는 결과)

## 4. 측정 원장

- `experiments/LEDGER.tsv`는 **append-only**이고 코드가 씁니다(`tools/ledger.py`). 손으로 고치지 않고, 정정도 새 행입니다.
- 실패한 측정도 기록합니다(`status=fail`).
- 해시는 손으로 적지 않습니다. 훅이 원장 값과 대조합니다.
- 원본(수집 원본, 원시 결과)은 덮어쓰지 않습니다. 산출물은 해시와 만든 스크립트로 잇습니다. 산출물 파일은 git 밖(`data/`)에 둡니다.
- 열 정의는 [LEDGER_SCHEMA.md](LEDGER_SCHEMA.md)에 있습니다.
- 2026-11-25 이전 측정(09 문서 M1~M11)은 원장 이전에 임시 스크립트로 잰 것이라 원장에 없습니다. 다시 잴 때 원장에 남깁니다.

## 5. 환경

- 프로젝트 Python 환경은 WSL Ubuntu의 venv 하나(`.venv/`, git 밖)만 씁니다. 다른 프로젝트 환경은 쓰지도 고치지도 않습니다. conda 대신 venv를 쓰는 이유는 [09 문서 9-1절](09_결정현황.md)에 있습니다.
- 패키지 목록은 **`env/requirements.txt` 하나**에 버전까지 고정합니다. venv, CI, 이후 Python 컨테이너 이미지가 모두 이 파일로 설치해서 서로 다른 버전이 섞이지 않게 합니다. 설치: `.venv/bin/python -m pip install -r env/requirements.txt`
- 인터프리터는 절대경로(`.venv/bin/python`)로 부릅니다. 환경을 켜는 명령(`activate`)에 기대지 않습니다.
- 패키지를 더하면 같은 커밋에서 환경 선언 파일을 고칩니다(`chore(env):`). 새 패키지는 묻고 더합니다.
- 설치 파일은 공식 배포처에서만 받고, 받기 전에 이름·크기를 알리고, SHA256을 확인해 기록합니다.
- 하드웨어 실측은 `env/hw-YYYYMMDD.md`로 남기고, 바뀌면 새 파일을 만듭니다.
- 원격 PC에서 긴 PowerShell은 스크립트 파일로 실행합니다. 공백이 있는 경로는 인자 하나의 문자열 안에서 따옴표로 감쌉니다.
- 원격 PC의 push는 저장소 전용 deploy key로 합니다. 계정 전체 로그인을 원격 PC에 두지 않습니다.
